## Naming Standard (candle indices) — CANONICAL, adopted 2026-09-23

Every name that holds a candle index says WHICH kind of candle it is. The test, in the user's words:
**"Does it serve as an endpoint in our structure? Or are we simply trying to record an extreme price?"**
A candle can be both an anchor and an extreme — the name follows the PURPOSE of the log, never the
coincidence.

| Kind | Spelling | Meaning |
|------|----------|---------|
| **Moment** | past participle `*_established_idx`, `*_confirmed_idx`; `*_at` stamps (`confirmed_at`, `ImbalanceInstance.formed_at`) and parameters (`evaluated_at`); `apply_idx` and `*_apply_idx` (`last_pullback_apply_idx`, `pullback_apply_idx`, `proximity_apply_idx`) | the candle at which something became knowable / took effect — real-time; the ONLY kind a timing or lifecycle read may use |
| **Pattern anchor** | `pattern_anchor_idx` (first candle), `pattern_end_idx` (last candle) | *Candle-pattern realm* (breakout / pullback / reversal patterns; the MS scan candle; the reversal close-break candle): "anchor" ALWAYS means the pattern's FIRST candle |
| **Market-structure anchor** | `*_anchor_idx` (`cts_anchor_idx`, `bos_anchor_idx`, KL-zone / fib anchors, a structure's start) | *Market-structure realm* (BOS/CTS of a cycle, zones, fibs, structures, subs): an ENDPOINT — start or end — of a structure element. Always a location, never a moment |
| **Extreme** | `*_extreme_idx` / `*_extreme_price`; `pattern_extreme_idx` / `pattern_extreme_price` | a recorded price extreme that is NOT serving as an endpoint at that site: window / retrace searches, running extremes, "is this a new extreme" checks, lower-TF price-mapping, candle anatomy, and the extreme reached INSIDE a pattern (from its first candle through its apply candle) |
| **Bare element idx** | `bos_idx`, `cts_idx` on a record that pairs them with a price (FibState / fib_lifecycle.csv, final.csv, cycle-0 dicts) — never an event or zone META key: those say `*_anchor_idx` (`RANGE_STARTED.meta["cts_anchor_idx"]` with `cts_price`; POI `meta["bos_anchor_idx"]` / `["cts_anchor_idx"]`, equal to the owning fib row's `bos_idx` / `cts_idx`) since Post-E·4 | that element's anchor |

Status (Plan E E5, 2026-09-25): the code, the current specs and the tracked skills follow this standard. Post-E·4
(2026-09-29d, PLAN_E §9.5) renamed the four exported meta keys the user scoped: `BOS_CONFIRMED` `pb_start` →
`last_pullback_apply_idx` (a moment: the last pullback pattern's apply candle), `RANGE_STARTED` `cts_idx` →
`cts_anchor_idx`, POI `bos_idx` / `cts_idx` → `bos_anchor_idx` / `cts_anchor_idx` (saves before it carry the old keys).
Post-E·5 (2026-09-30, PLAN_E §9.6) closed the three its landing review found still non-standard: fib meta
`cycle1_bos_idx` → `cycle1_bos_anchor_idx` (BOS_1's anchor on the cycle-1 cross fib; retired with its emitter in
PLAN_I S4), KL meta `pb_reconfirm_idx` →
`reconfirmed_idx` (the CTS_RECONFIRMED moment), and KL meta `expanded_last_idx` deleted with its `_price` / `_event`
siblings (copies of `bounds_steps[-1]`; saves before it carry all three).
PLAN_N (2026-10-12, `plans/PLAN_N_naming_audit.md`) audited the keys Plan E never did: KL `bounds_steps[*].start_idx`
(one key, two kinds) → `base_idx` on INIT / `expanded_idx` on an expansion; `RANGE_STARTED` `start_idx` / `confirm_idx`
→ `range_anchor_idx` (on every path — MS's range start) / `confirmed_at`; `STATE_CHANGED.effective_idx` == `ev.idx` on
every row (the range start it carried on `range_confirmed` rows lives on `RANGE_STARTED`); and "degenerate parent
cycle" → "collapsed parent cycle" (one test, one name). Saves before it carry the old keys / reason.
Kept by decision: frozen event names (bridged by `ARCHITECTURE.md` "`ev.idx` convention") and event-type
tokens / legend labels; `KLZone.source_time` (a moment's time next to the anchor's `source_price`) and
`StructureLevel.time` (the anchor's time) — PLAN_E Q12; the reversal-scope names (`_synth_reversal_trigger`'s
`reversal_apply_idx` …, PLAN_E Q14 — a separate pass; the orchestrator's `reversal_confirmed_by_sid`, which held a
SCHEDULED candidate apply, became `reversal_idx_by_new_sid` = the realised reversal on 2026-09-27, so FibTracker's
`reversal_confirmed_idx` is now accurate); moment names that predate the `*_established_idx` spelling
(`ParentTables.cts_moment` and its builder's local `bos_moment`, `TrueFirstBreakout.est_idx`); run.log labels (`cts0_est=`,
`[fib] CTS idx=`); the `debug/zone_proximity_diag.py` CSV columns; `probe_input_idx` / `parent_input_idx` name a
ROLE (the probe's M15 input / the parent trigger's H1 input), not a kind — per trigger type an MS anchor or an extreme (see their rows; Plan E Post-E·1). Dated history — landed plans, "as landed" / "history" notes, bug
narratives — keeps its original wording: there "the CTS/BOS **extreme** (at confirmation)" for
`CTS_ESTABLISHED.idx` / `BOS_CONFIRMED.idx`, `CTS_CONFIRMED.meta["cts_anchor_idx"]` or a KL-zone
`meta["anchor_idx"]` means the CTS/BOS **anchor** (`CTS_ESTABLISHED.idx` / `BOS_CONFIRMED.idx` were the
anchors until Plan E E4a / E4b made them the MOMENT; the anchors are `meta["cts_anchor_idx"]` /

above): `ev.price` stays the ANCHOR's price after the flip (PLAN_E Q19). The fib

`FIB_LIFECYCLE_SPEC.md` §15.3).

A different field from the zone's market-structure `anchor_idx`: equal to it for inside-bar / 1-candle / catch-all bases, `anchor_idx − 1` for star bases and some 2-candle bases (equal on 31 of 39 zones on the reference window). |

| **inner threshold** | Zone boundary price closer to current price |
| **KL zone** | Key Level zone — derived from CTS/BOS confirmation events |

## Timing Terms

| Term | Definition |
|------|------------|
| **apply_idx** | Candle where pattern effect is applied (`end_idx` on SUCCESS, `confirmation_idx` on CONFIRMED). On `REVERSAL_CANDIDATE.meta` it is the SCHEDULED apply — a prediction, unrealised when a new cycle ends the watch or an earlier reversal lands (until 2026-09-29 a watch expiry could also discard it). |
| **confirmed_idx** | Candle where zone becomes confirmed for charting |
| **confirmed_at** | The MOMENT field in event meta — the candle at which the event became knowable. `CTS_ESTABLISHED` / `BOS_CONFIRMED`: the breakout pattern's apply candle = the cycle's CTS-established **moment** (one value for both events of a cycle, by construction); `== ev.idx` since Plan E E4a (`CTS_ESTABLISHED`) / E4b (`BOS_CONFIRMED`), 2026-09-25; their anchors (price locations, which can precede it) are meta `cts_anchor_idx` / `bos_anchor_idx`. `CTS_CONFIRMED` / `CTS_RECONFIRMED`: the confirmation candle, == `ev.idx`. Pattern-path `CTS_UPDATED`: the pattern's apply candle (since Plan E E3·0; `== ev.idx` since E4c); absent on a raw-path `CTS_UPDATED` (its `ev.idx` is its moment). Canonical per-event table: `ARCHITECTURE.md` "`ev.idx` convention". |
| **moment** | The candle at which an event / level becomes knowable in real time (vs the anchor, a historical price location — `ev.idx` of `CTS_ESTABLISHED` / `BOS_CONFIRMED` / pattern-path `CTS_UPDATED` before Plan E E4a / E4b / E4c; since then every CTS / BOS event's `ev.idx` IS its moment — `REVERSAL_CANDIDATE`'s is still its pattern's first candle, its moment `meta["apply_idx"]`). Every timing / lifecycle read uses the moment (`ef.event_moment`), never a raw CTS / BOS `ev.idx`. For a cycle: the **CTS-established moment** = `CTS_ESTABLISHED.meta["confirmed_at"]` (see "cts_moment / CTS-established moment" under "Sub-Structure Pool Terms"). |
| **event_moment** | `structure/event_fields.event_moment(ev)` (Plan F, 2026-09-24, in `market_structure`; moved + extended by Plan E E2a — call it qualified, `ef.event_moment(ev)`) — an event's moment in code: `CTS_ESTABLISHED` / `BOS_CONFIRMED` → `meta["confirmed_at"]` (== `ev.idx` since Plan E E4a / E4b); `CTS_CONFIRMED` / `CTS_RECONFIRMED` / `CTS_THRESHOLD_UPDATED` / `BOS_THRESHOLD_UPDATED` (Plan E E3g-2) → `ev.idx`; `CTS_UPDATED` → `ev.idx` on the raw path, `meta["confirmed_at"]` (the apply candle) on the pattern path (recorded since Plan E E3·0); any other type raises `ValueError`. Its anchor siblings in the same module: `ef.cts_anchor_idx` / `ef.bos_anchor_idx` / `ef.pattern_anchor_idx`. FibTracker asks its imbalance questions at it (see `evaluated_at` under "Imbalance Terms"). Canonical per-event table: `ARCHITECTURE.md` "`ev.idx` convention". |
| **start_idx** | Logical start of a structure (`RANGE_STARTED` carried a range's start under this name until PLAN_N N2 — now `range_anchor_idx`). On the sub-structure pool objects (`TriggerRecord`, `PooledStructure`, sub `SidRecord`) and on KL/POI/fib lifecycle meta, `start_idx` is a REAL-TIME lifecycle value — never confuse it with `starting_idx` (the historical structural anchor / pool key; see "Sub-Structure Pool Terms"). |
| **range_anchor_idx** | `RANGE_STARTED.meta["range_anchor_idx"]` (PLAN_N N2 / N5, 2026-10-12; `start_idx` until then, and absent on the pullback / proximity paths) = MS's own range start `st.range_start_idx` — a market-structure ANCHOR: the range-label candle on the label path (2–5 candles before the event's moment), the CTS anchor on a pullback- / proximity-created range (= that event's `cts_anchor_idx`). The H1 range box starts there. Its moment is `meta["confirmed_at"]` (== `ev.idx`; `confirm_idx` until PLAN_N). The MS df columns `range_start_idx` / `range_confirm_idx` and the label column `is_range_confirm_idx` keep their names (not event meta) |
| **too_early** | Flag when identify_start finds extreme before min_history |
| **the three clocks: anchor / moment / lifecycle** | (Named 2026-10-19, PLAN_R round 4 #9 — the user's "would have been" time.) **Anchor** = a historical price LOCATION (`cts_anchor_idx`, `bos_anchor_idx`, `starting_idx`, a POI's `ic_idx`). **Moment** = when the structure's own logic knew it, ignoring any lifecycle — the "would have been" time: every CTS / BOS `ev.idx` since Plan E, `ef.event_moment`. The proximity scan runs on it (why the collapsed H1 cycle (1,1) still fires 820 / 871), as do the parent tables' `cts_moment`. **Lifecycle** = real time: a structure's / cycle's / zone's / sub's active window `[start_idx, end_idx)`, clamped (`floor`, the `structure_lifecycle` clamps) — empty on a collapsed cycle; zone records carry clamped times (`confirmed_idx`), events carry moments. Never mix the three (Critical Constraints: lifecycle fields are real-time, pattern-definition fields historical). |

## Event Terms

| Term | Definition |
|------|------------|
| **event.idx** | Candle index stamped on the event — the moment it became knowable, on every CTS / BOS event since Plan E E4 (2026-09-25; the exception: `REVERSAL_CANDIDATE` stamps its pattern's first candle, its moment is `meta["apply_idx"]`): `CTS_ESTABLISHED` / `BOS_CONFIRMED` / pattern-path `CTS_UPDATED` stamped their anchor before E4a / E4b / E4c, now in `meta["cts_anchor_idx"]` / `meta["bos_anchor_idx"]` / `meta["cts_anchor_idx"]`. `ev.price` stays the anchor's price (PLAN_E Q19). Canonical per-event table: `ARCHITECTURE.md` "`ev.idx` convention". |
| **event.meta** | Dictionary of event-specific metadata |
| **STATE_CHANGED** | Transition between market states (e.g., cts → bos) |
| **CTS_ESTABLISHED** | A new CTS cycle established by a breakout pattern (emitted together with that cycle's `BOS_CONFIRMED`). `idx` = `meta["confirmed_at"]` = the apply candle (the moment; Plan E E4a, 2026-09-25); `meta["cts_anchor_idx"]` = the CTS anchor — the pattern's extreme candle, adopted as the cycle's CTS (`ev.idx` before E4a), whose high / low `ev.price` holds; `meta["pattern_anchor_idx"]` = the breakout pattern's FIRST candle (the pattern-realm anchor) — not necessarily the CTS anchor (the two coincide when the first candle holds the extreme; never on the reference window, 0 of 34). |
| **CTS_UPDATED** | The current (unconfirmed) CTS point was (re)stamped. Raw path (`meta["via"] == CTS_UPDATED_RAW_VIA`, `"replay_raw"`, the constant in `structure/event_fields.py`): a new wick extreme; `idx` = the processed candle = the moment. Pattern path (`via` = a pattern name — a breakout while the cycle is unconfirmed, emitted ONLY when its pattern extreme is a strict new extreme, the raw path's rule, since 2026-09-27; the CTS never regresses — MARKET_STRUCTURE_SPEC "CTS"): `idx` = `meta["confirmed_at"]` = the apply candle, the moment (recorded since Plan E E3·0; the idx since E4c, 2026-09-25); the new CTS anchor — the pattern's extreme candle, `ev.idx` before E4c — is `meta["cts_anchor_idx"]`, since 2026-09-27 always the apply candle (every span candle before the apply candle was raw-processed in the back-fill, so none lies beyond the current CTS (one that did became the CTS: a tie); only the apply candle, not yet raw-processed, can be a strict new extreme, so a pattern whose extreme sits earlier emits nothing; before, such a tie was emitted as a same-idx/price duplicate of the raw update — see `ARCHITECTURE.md` "`ev.idx` convention"). |
| **CTS_CONFIRMED** | Continue-the-structure level confirmed |
| **BOS_CONFIRMED** | Break-of-structure level confirmed (emitted together with the cycle's `CTS_ESTABLISHED`). `idx` = `meta["confirmed_at"]` = the apply candle (the moment; Plan E E4b, 2026-09-25); `meta["bos_anchor_idx"]` = the BOS anchor — the swing extreme, the level (`ev.idx` before E4b), whose price `ev.price` holds |
| **RANGE_STARTED** | New consolidation range detected |
| **RANGE_UPDATED** | Range bounds expanded |
| **RANGE_RESET** | Range closed (breakout or reversal) |

## Wave Candle Terms

| Term | Definition |
|------|------------|

| **BIB (base inside bar)** | Zone base pattern requiring special forward/backward search logic for wave candles |

## WVMI Terms

| Term | Definition |
|------|------------|
| **WVMI** | Wave Volume Momentum Indicator — measures BOS zone strength via volume ratios of wave candle pairs |
| **breakout momentum** | `(LB_vol * LB_weight) / FB_vol` — locked at CTS_n confirmation |
| **pullback momentum** | `(LP_vol * LP_weight) / FP_vol` — shifts until BOS_n+1 locks it |
| **last wave weight** | Weight (0.5/0.7/1.0) applied to LB/LP volume based on candle type and size |
| **temporary LP** | The Last Pullback of an unlocked WVMI record: moves to each qualified candle closing further in the pullback direction, the first one chosen by how the CTS confirmed (WVMI_SPEC "Temporary LP Selection", since 2026-10-26 — the qualified close nearest the BOS zone's outer before); finalizes on BOS_n+1 |
| **per-LP row** (`WVMILPRow`) | One LP a WVMI record has had — every temporary LP and the locked one, one mark each above the chart's volume bars (a sub's a dot, an H1 record's a circle — CHARTING_SPEC §13, step 5) (`WVMIRecord.lp_rows`; "WVMI back on the chart" step 4, 2026-10-26): `lp_idx`, `as_of_idx` (the candle it became the LP), `lp_status` ∈ `temporary` / `locked` / `open` / `unlocked` with `lp_status_reason` / `lp_status_idx` (why / when), the row's `pullback_momentum`. Exported one row per dot to `*_wvmi_lps.csv` (collapsed records none). WVMI_SPEC "Per-LP rows" |
| **buy_momentum / sell_momentum** | Direction-labeled wrappers: buy zone → buy=breakout, sell=pullback; sell zone → reversed |
| **vol_dir** | Volume direction column: +1 (buying pressure), -1 (selling pressure), 0 (neutral/no signal) |
| **collapsed cycle** | (One test, one name since PLAN_N N4 — `ParentTables` calls an H1 parent cycle that fails it a "collapsed parent cycle".) A structure cycle whose `compute_cycle_lifecycle` window is EMPTY: clamped `start >= end` (e.g. a sub cycle established and confirmed before the sub's `start_idx`, whose start clamps to the floor past its end; H1's retroactive post-reversal cycles). | **cycle_collapsed** | `WVMIRecord` bool field (Plan G G2, 2026-09-30; main and subs): the record's cycle is a collapsed cycle (`start >= end`, end not None — an open cycle is never collapsed). Exported as the `_wvmi.csv` column right after `lp_locked`. A flag only — WVMI has no lifecycle of its own. Equal, per cycle, to the KL rendering's `collapsed_cycles` |

## Pattern Terms

| Term | Definition |
|------|------------|
| **pinbar** | Single candle with long wick rejecting price level |
| **pinbar body floor** (`pinbar_body_floor`, `is_floor_pinbar`, `candle_type_before_floor`) | A body-% maru / normal whose real body is strictly below its candle's floor is classified `pinbar` (`classify_candles` step 4); `is_floor_pinbar` marks those, `candle_type_before_floor` keeps the body-% type, `pinbar_body_floor` the floor itself (price units, NaN = none). A per-candle column since PLAN_U U1 (2026-10-28; today the fixed per-TF value); canonical `features/CANDLE_BODY_FLOOR_NOTES.md` |
| **star** | Small-bodied candle indicating indecision |
| **long-tail** | Candle with extended tail showing price rejection |
| **maru** | Strong-bodied candle (marubozu-like) |
| **breakout pattern** | Multi-candle pattern signaling structure break |
| **break vs go past** | A **break** = a valid PATTERN crossing a threshold (a breakout, pullback or reversal pattern — `detect_best_for_anchor` with `check_break`: the close beyond the threshold); a price that merely crosses a level **goes past** / surpasses it (a wick, a raw CTS update). Say "the CTS went past the BOS anchor price", never "broke", unless a pattern did (the user, 2026-10-09, PLAN_H §6 RX1-T) |
| **agreed direction** | One direction per candle from its candle `direction` (sign(c − o)) and `vol_dir` (sign(c − prev c)): ±1 with vol the same or 0 → that direction; ±1 with vol opposite → a **split candle**; 0 with vol ±1 → a **volume-only doji** (directional); 0 / 0 → a **true doji** (0). `features/candles_v2.agreed_direction` (`AGREED_SPLIT` marks a split). The institutional pattern's legs and its IC candidates read it (PLAN_H §1 item 2, V1a / VD) |
| **split candle** | Candle and volume direction opposite — belongs to no institutional-pattern leg, breaks every leg run, never an IC |
| **volume-only doji** | A doji (o == c) whose close moved (vol ±1): an ordinary directional candle for the legs — it can be the IC (type `pinbar`, body 0) |
| **true doji** | A doji with vol 0 (agreed 0): never breaks a leg run, a full member (cap + multi) of the leg it is assigned to; never the pattern's first or last candle (E1) |
| **institutional pattern (IP)** | Initial leg (agreed sd) · opp leg (agreed −sd; the IC = its last candle) · continuation leg (agreed sd, a big maru with a body strictly greater than the opp leg's), ranked 1A–3D + shape i–iv (`ip_rank`, e.g. "2A.i"); Step 2 of IC identification: the best pattern among the **IC candidates** (Step 1B's passers when the prior-imbalance preference applies — PLAN_S step 3), then the **tiebreak rules**. Canonical: `plans/PLAN_H_institutional_pattern_poi.md` §1; code `patterns/institutional_pattern.py` + `zones/poi_zones.select_institutional_pattern` (run by `select_ic`). Exported by landing A; since landing B (2026-10-06) THE POI selection — the drawn POI and MS's sd-proximity read (POI_ZONES_SPEC §3.4) |

## Zone Proximity Terms

| Term | Definition |
|------|------------|
| **zone proximity trigger** | A candle where price wicks within `proximity_pips` of a side's **proximity reference** (a zone's inner bound). Computed by `check_zone_proximity` in `zones/zone_proximity.py` (each cycle's `CycleProximityScan`). |
| **sd proximity reference / opp_sd proximity reference** | (PLAN_R, 2026-10-20; the user asked for "proximity" in every name — "reference" alone clashes with the probe's `ReferenceZone` and the IC `ic_ref_*`.) The zone inner each side triggers on at a candle: a usable, unpassed rung of that side's **proximity reference ladder**, kept or moved through the **proximity reference gate** (PLAN_R §9; steps 1–2: simply the closest one to the other side, "the smallest gap available"). Ties (equal inners) among candidates: the parent zone first, then a sub's BOS before its POI; a current reference keeps its place against an equal-inner candidate (one not strictly inside it). A trigger's `zone_kind` / `trigger_inner` = it. |
| **proximity reference ladder** | A side's candidate zones (rungs), ordered by closeness to the other side. sd: the cycle's POI(s) closer than its BOS inner, then the BOS — the LAST rung (a POI at / beyond the BOS is unreachable). opp_sd: the CTS — the last rung. PLAN_R step 2 adds the **proximity overlay** (sub zones). |
| **passed proximity zone** | A ladder rung an H1 close has gone strictly beyond the outer of (the outer as of that close; a close AT the outer or a wick beyond it is not a pass). Out of the ladder for the rest of the cycle, from the NEXT candle; tested on every candle, also one where a gate blocks the trigger; the last rung is never tested. A side LOCKS when its passed reference gives way to its last rung (never by default); the sd lock is permanent, an opp_sd lock is lifted by a NEWER counter-sub zone (PLAN_R step 2). |
| **proximity reference gap** | The SIGNED distance between the two references: `sd × (opp_sd reference − sd reference) / pip`, rounded half-up (`floor(g + 0.5 + 1e-9)`); crossed references give ≤ 0. Meta `prox_ref_gap_pips` on each trigger. |
| **proximity reference gate** | (PLAN_R §9, the user's round-15 rule, 2026-10-20: "We only make updates when the updated gap remains above the given threshold") A side's proximity reference is UPDATED only if the proximity reference gap after the update stays above `DEFAULT_MIN_PROXIMITY_REFERENCE_GAP_PIPS` (H1 40 / M15 25 / M5 15; > `proximity_pips`); a too-narrow (`<=`) update is skipped and the reference stays. Each side starts on its last rung; a PASSED reference moves first (outward — always allowed), then each other side takes the closest rung inside its reference that passes against the updated other side. No counters: alternation is unlimited. Replaced steps 1–2's **narrow proximity-reference cap** (per-side counters while the gap was `<=` the minimum). |
| **narrow parent-reference exception** | (PLAN_R §9.1) A cycle whose parent BOS–CTS INNER gap is `<=` the gate's minimum (static from CTS_CONFIRMED — inners never move): both references stay on the parent BOS / CTS and the cycle fires at most one sd + one opp_sd trigger (gate label `narrow_parent_refs`). The only proximity-reference cap left; Rules 1–3 read the THRESHOLD gap, a different measure. Meta `narrow_prox_ref` (the gap at the candle's start `<=` the minimum) is True only here. |
| **superseded reference** | (PLAN_R §9.2) The current proximity reference, unpassed, no longer on its ladder (its source sub was replaced by a newer one, or the source's newer cycle took over). It STAYS the reference — never a fall back to the parent CTS / BOS (round 15) — and stays pass-testable, unless a rung inside it passes the gate or the ladder's closest rung is outward of it. |
| **proximity overlay** | The sub zones added to a side's ladder (PLAN_R step 2): counter-sub BOS / POI zones on the opp_sd side; same-direction sub zones beyond the parent POI on the sd side. `prox_ref_source = "sub"` on a trigger that fired on one. |
| **opp_sd zones proximity trigger** | An opp_sd zone proximity trigger (was "CTS zone proximity trigger", renamed by PLAN_R: from step 2 the opp_sd reference can be a counter sub's zone). The var 3 detector fires on it; internal names `prior_opp_sd_prox_idx` / `opp_sd_prox_zone_kind` (were `prior_cts_prox_idx` / `cts_prox_zone_kind`, in-memory trigger meta). |
| **sd zone** | A zone in the structure direction. For sd=+1: buy-side zones (BOS KL + POI). For sd=-1: sell-side (BOS KL + POI). POI zones are always sd by Fib construction (Fib spans BOS→CTS). For the proximity scan a POI counts like the BOS KL zone — at every candle of its cycle's scan, never by its activation history (PLAN_Q, 2026-10-14). | **opp_sd zone** | A zone opposite to the structure direction. For sd=+1: sell-side; for sd=-1: buy-side. A structure's OWN opp_sd zone is its CTS KL zone only (no structure has opp_sd POIs of its own); since PLAN_R step 2 the parent's opp_sd proximity ladder also reads its counter subs' BOS zones and POIs (the proximity overlay). |
| **triggered_by_event_idx** | `WVMIRecord.meta` (Part 4 §8.7 attribution schema), with `triggered_by_event_type`. ROLE by entity: on a MAIN record, the candle of the cycle's first zone-proximity trigger when it is sd — ATTRIBUTION since 2026-10-26 ("WVMI back on the chart" step 2, a declared rule-3 meaning change: every H1 cycle with a CTS_CONFIRMED has a record; None, an empty CSV cell, when the cycle has no first sd trigger), the GATE that created the record before (the first_counter `MultiTFTrigger.meta["trigger_event_idx"]` is the same candle — read from the proximity lists directly since 2026-10-26, `zone_proximity.first_sd_proximity_triggers`, it carried this value until then; its unread `probe_end_idx` copy was deleted in Plan E E1b). On a SUB record (Plan G, 2026-09-30 — a declared rule-3 meaning change): per lens, the lens's first WVMI-class parent trigger inside the sub's `[start_idx, m15_end_idx]` — ATTRIBUTION, not a gate (the record exists regardless); PARENT-df (H1) coordinates, never translated; None (an empty CSV cell, nullable `Int64`) when no trigger of the lens lands in the window. |
| **V / lambda movement** | Alternating retracement pattern within a structure cycle: price moves toward sd zone, bounces, moves toward opp_sd zone, bounces back, etc. The zone-proximity state machine captures each leg. |
| **proximity_pips** | The pip threshold for zone proximity detection. Defaults: H1=8, M15=5, M5=3 (`zones/zone_proximity.py` `DEFAULT_PROXIMITY_PIPS` — the one source). Caller-overridable per call. |

## Cross-Fib Limit Terms (PLAN_I, the cross-cycle fib revamp — S2 2026-10-07: stamped, applied from S3; canonical `plans/PLAN_I_cross_cycle_fib_revamp.md` §1.2 / §4 / §9.3)

|------|------------|
| **cross fib limit** | The rule (PLAN_I §1.1): a cross fib may target cycle T iff the structure has a reference price `P` and no cycle k < T has a latest CTS anchor **beyond** `P`; every later cycle is single; no `P` → no cross. S2 stamps the fields below on every fib record; S3 applies the rule to subs (`FibTracker._cross_allowed`: a cycle past the limit gets the single, `via: "cross_fib_limit"`, no pre-established cross; no limit entry → `CrossFibLimitError`), S4 to main — ONE FibTracker logic since S4 (`zones/CROSS_CYCLE_FIB_SPEC.md`). |
