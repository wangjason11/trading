JOB A: what "anchor" means (50 rows)
- The word has seven different meanings in the code; the counts are in anchor_meaning_counts.
- The bare key anchor_idx alone means three things: a pattern's FIRST candle on CTS_ESTABLISHED and REVERSAL_CANDIDATE, the close-break candle on REVERSAL_WATCH_START, and the price EXTREME on KL zones. Both keys pass through the same mirror key lists in entity_df_mutation.py:103-124.
- The user's recollection is half right. CTS_CONFIRMED and CTS_RECONFIRMED use anchor = extreme (cts_anchor_idx). CTS_UPDATED has no anchor key at all. CTS_ESTABLISHED.anchor_idx is the breakout pattern's first candle.
- Other collisions:
  - "anchor" means the first candle in detect_best_for_anchor but the last candle in _price_confirmation.
  - Prose calls base_idx the anchor. This is wrong: base_idx is the base pattern's first candle.
  - "clear pullback anchor" refers to a moment.
  - The fib "START ANCHOR" is the BOS end of the fib span.
  - One reversal candle carries four or more names.
- Correction to the partials: REVERSAL_WATCH_START.anchor_idx, rv_anchor_failed and _schedule_reversal_from_anchor refer to the close-break candle from the per-candle replay. That candle can be a back-fill candle, so it is not the MS scan candle.
- A template already exists in the code. TrueFirstBreakout has anchor_idx (pattern start), est_idx (MOMENT) and extreme_idx (LOCATION). unified_probe's docstring states the rule "confirmed_at for timing, .idx for where the extreme sits".

Proposed standard
- Past tense *_established_at / *_confirmed_at / *_moment_idx means a MOMENT. *_extreme_idx means a price LOCATION.
- pattern_start_idx and pattern_end_idx name candles inside a pattern.
- close_break_idx names the reversal close-break candle.
- scan_idx names the MS loop candle.
- starting_idx stays as the structural start.
- "fib anchor" is either retired or kept as the only reserved sense of the word.
- Frozen keys get additive aliases, never renames, and every new idx-bearing key must be added to _EVENT_META_IDX_KEYS.
- For CTS_ESTABLISHED's new extreme key, use cts_extreme_idx, not cts_anchor_idx. The event already carries anchor_idx for the pattern start. Add cts_extreme_idx as an alias on CTS_CONFIRMED and CTS_RECONFIRMED too.

Existing naming violations: cts_confirmed_for_idx, StartDecision.meta last_cts_confirmed_idx, the structure_engine locals cts_est_idx and cts_established_idx, the POI meta cts_established_idx, the fib meta activated_at, and the log label cts0_est. All of them hold EXTREMES.

JOB B: reads of ev.idx (74 rows)
- 69 production/debug rows: 26 LOCATION, 18 TIMING, 17 BOTH, 4 AMBIGUOUS, 4 neither/raw. The other 5 rows are test groups.
- What breaks under an EST flip (must move to an explicit extreme key first):
  - reference_zone._extreme_idx_for_cts_event. In production it feeds the H1 main reversal probe input and the sub sibling/reversal inputs, i.e. the sub pool keys.
  - FibTracker's cts_idx: the fib 100% point, the IC scan range, the imbalance ranges and the new-extreme guards.
  - The wave-candle CTS BIB scan.
  - The CTS dots on the H1 chart, on the M15 subs and on the M15 H1 overlay.
  - structure_levels.csv time and the cts1_ext log labels.
  - The location half of POI cond1.
- What becomes correct:
  - The POI activation gate (Plan D). Verified live instance: confluence sub 0 cycle 2 would move 1223 -> 1224.
  - The fib activated_at / new_cycle terminal. Verified live instance: sub 3 cycle 0's fib end would move 2828 -> 2829 on both lenses.
  - knowable_at_idx (closes §17.12 for EST).
  - The reference_zone causal window and recency sort.
  - The unified_probe Phase-2 check_lo, which today disagrees with Phase 1.
  - scenario1_revert, and the unread lifecycle_end_idx.
- The crux: many sites use one value in both roles. In fib and cross_cycle_fib, current_candle and anchor_idx are both cts_idx. The POI transitions do the same, and so do the has_unfilled_imbalance range/as-of calls. These cannot be reinterpreted in place; each call has to be split into (moment, extreme) first.
- Needs a user decision: the Scenario 1 test `CTS_0 idx >= reversal_confirmed_idx`.
- BOS_CONFIRMED lags on all 34 rows. A BOS flip would additionally move the KL BOS zones, the fib BOS point, cycle1_bos_idx, the first_confluence probe input (every FC pool key), the prev-BOS lines, every BOS dot, and the struct_start base (masked downstream). _emit_bos_confirmed builds MS state from the same idx argument, so the emitter must be decoupled first.

Hazards I found beyond the partials
1. The orchestrator's (idx, type) sort. After a flip, an sd-prox CTS_CONFIRMED can tie its cycle's EST moment, and 'CTS_CONFIRMED' sorts before 'CTS_ESTABLISHED', so on_cts_confirmed would run before on_cts_established.
2. Prior-cycle CTS_THRESHOLD_UPDATED events in [extreme, moment) would be dispatched while the phase is still pre_established.
3. BOS-before-EST ordering holds only by alphabetical accident.
All three have 0 instances on the window. The fix is an explicit type rank in the sort before any flip.

Blast radius on the baseline
- EST: 2 unique events, 3 CSV rows (confluence 1223/1224 and 2828/2829; counter 2828/2829), and 0 of 5 on H1. An EST flip is zero-delta on H1.
- BOS: 34/34 rows lag (H1 14-76 candles, confluence 2-411, counter 4-285).
- CTS_UPDATED: 53/259/114 rows, of which 7/23/7 are pattern-path rows with no recorded moment.
- Tests: 6 pins break outright (listed in the test rows). test_main_reversal_probe.py:212-219 already asserts idx == moment, which contradicts test_ms_cts0_scan.py:75.

Recommended sequence, each step its own /compare
1. Add cts_extreme_idx (and bos_extreme_idx) as meta keys, add them to _EVENT_META_IDX_KEYS, and migrate every LOCATION read to them. This step should be byte-identical.
2. Make the event ordering explicit with a type rank.
3. Flip the idx at the emit site only: pass apply_idx at market_structure.py:1485 and keep st.cts as the extreme Point. Expected deltas: POI 1223 -> 1224 and fib end 2828 -> 2829, plus any timing reads split in step 1.
4. Treat a BOS flip as a separate, much larger change.

### vocabulary_proposal

STANDARD. One rule per suffix. It applies to every new or renamed identifier, meta key, CSV column and prose term.

1. MOMENT: the candle at which something became knowable or took effect.
   - Spelled `*_at` for event and lifecycle stamps: confirmed_at, activated_at, locked_at, deactivated_at, reactivated_at.
   - Spelled `*_moment_idx` for derived values and params: cts_moment_idx, bos_moment_idx.
   - Any past participle in an idx name also means a moment: *_established_idx, *_confirmed_idx, *_updated_idx, *_activated_idx.
   - Already compliant: confirmed_at; apply_idx (the pattern's apply candle); trigger_idx; probe_finalize_idx; TrueFirstBreakout.est_idx; ParentTables.cts_moment; lifecycle start_idx / end_idx / trigger_end_idx.
   - `confirmed_at` on CTS_ESTABLISHED and BOS_CONFIRMED is documented as the universal "moment" key, not the CTS_CONFIRMED concept.

2. LOCATION: the candle that holds a price high or low.
   - Spelled `*_extreme_idx`, paired with `*_extreme_price`: cts_extreme_idx, bos_extreme_idx, or a generic extreme_idx in shared helpers.
   - A location field is never used as a time. A timing read of an `*_extreme_idx` is a bug you can see from the name.

3. CANDLES INSIDE A PATTERN:
   - pattern_start_idx = the pattern's first candle (breakout, reversal, pullback, range or base pattern). It replaces every "anchor" used in this sense.
   - pattern_end_idx = the pattern's last candle.
   - confirmation_idx = the existing PatternEvent field.
   - apply_idx = a moment (rule 1).

4. NAMED CANDLES:
   - close_break_idx = the reversal-watch candle whose CLOSE broke bos_threshold. It can be a back-fill candle, so it is not necessarily the scan candle.
   - scan_idx = the candle MarketStructure is stepping.
   - base_idx = the FIRST candle of a KL base pattern. The key stays; the prose "zone anchor candle" is wrong and gets corrected.
   - ic_idx is unchanged.

5. STRUCTURAL START:
   - starting_idx = historical structural start (the pool key). start_idx = real-time lifecycle start. Both names stay.
   - Prose says "structural start", never "structural anchor".
   - The main SidRecord.creation_event_idx (min ev.idx) is split from the sub meaning and renamed first_event_idx.

6. FIB: the endpoints are extremes, so they are called "fib BOS extreme" and "fib CTS extreme". "Fib anchor" is retired.

7. "ANCHOR" IS RETIRED from every engine-owned identifier, key, CSV column, style key and prose. Only these survive:
   - (a) The FROZEN event-meta keys and value, each given a GLOSSARY entry with its true meaning and read only through accessors:
     - CTS_ESTABLISHED.meta["anchor_idx"] = breakout pattern start.
     - REVERSAL_CANDIDATE.meta["anchor_idx"] = reversal pattern start, which equals the close-break candle by construction.
     - REVERSAL_WATCH_START.meta["anchor_idx"] = close-break candle.
     - CTS_CONFIRMED / CTS_RECONFIRMED.meta["cts_anchor_idx"] = the current CTS extreme.
     - The reason value "rv_anchor_failed" = close-break.
   - (b) Plotly's xanchor / yanchor.
   - (c) features anchor_shift and the 12 `*_as0..2` columns in the H1 final.csv, unless a header rename is approved (Q11).
   - Your recollection is half right. CTS_CONFIRMED/RECONFIRMED do use anchor = extreme. But CTS_UPDATED has no anchor key (its ev.idx is the extreme), and CTS_ESTABLISHED.anchor_idx is the pattern's FIRST candle, not the extreme (anchor < extreme on all 34 rows in the baseline).

### risks

1. POOL KEYS / starting_idx
- reference_zone._extreme_idx_for_cts_event (:88-97) is the one CTS_ESTABLISHED read that sets probe inputs: sibling, reversal handoff and the H1 main reversal.
- If it is left unmigrated at the flip, any reference whose winner is a CTS_ESTABLISHED moves the probe input and the ad-hoc base candle to the moment. That changes starting_idx, the pool key, sub_id numbering, the probe-cache key (dir, input) and hit/miss behaviour.
- On this window it would be INVISIBLE: no probe used ref=cts_established. So /compare cannot catch it; a unit test with an EST winner and lag > 0 must pin it.
- The sibling site mixes timing and location inside one expression (entity_df_mutation.py:481-489), so it needs a careful split.
- For BOS, first_confluence input_idx is the pool-key input for every first_confluence sub.

2. Silent mixed-scale compares
- After an EST-only flip, the fib new-extreme guards (fib_tracker.py:1310, 1383, 1509, 2342, 2396) compare an UPD extreme against a CTS_ESTABLISHED moment. They silently drop an update in (extreme, moment]. There are 0 instances on the window.
- The poi cond1 has the same shape.

3. Chart dot positions
- The trailing-CTS dots on 3 charts would move 1-5 candles in x while y stays ev.price. _replacement_break_point inherits the shift.
- A BOS flip moves every BOS dot 2-411 candles. Unmigrated, it collapses every H1 fib (BOS moment == CTS_ESTABLISHED idx on all 5 H1 cycles), and with it the POIs.

4. Ordering
- The (idx, type) sort in the orchestrator and sub_wvmi holds BOS before EST only by alphabet.
- After a flip, an sd-prox CTS_CONFIRMED can tie the CTS_ESTABLISHED moment and run first ("CTS_CONFIRMED" < "CTS_ESTABLISHED"), and the fib then never locks.
- A prior-cycle CTS_THRESHOLD_UPDATED in [extreme, moment) would be dispatched while the phase is still pre_established (fib_tracker.py:2081-2084).
- MS emits the CTS_ESTABLISHED BEFORE the BOS_CONFIRMED, so a naive stable sort by moment breaks the fib loop.
- All have 0 instances on the window. Pin the sort keys in stage 1.

5. _EVENT_META_IDX_KEYS is unmaintained
- 9 keys already ship slice-local: pb_start, expires_idx, KL source_event_idx, POI bos_idx/cts_idx, fib activated_at / reactivated_at / locked_at / cycle1_bos_idx, WaveCandleResult anchor_idx.
- A new cts_extreme_idx or bos_extreme_idx that is not listed there would export wrong values on M15.
- Add a test that every *_idx / *_at meta key on mirrored sub events is entity-absolute.

6. The window barely exercises this
- Only 2 unique lagging CTS_ESTABLISHED cycles exist, so a zero-delta /compare proves little.
- Every migrated site needs a synthetic lagging fixture, e.g. test_unified_probe._make_second_cts_moment_after_extreme_data with (idx, confirmed_at) = (9, 10).

7. Fixture drift
- 18 test files build CTS_ESTABLISHED events. A strict accessor raises KeyError on old fixtures.
- An accessor that falls back to ev.idx is silently wrong after the flip. Use one factory, and never write .get(key, ev.idx).

8. MS internal state must stay on the extreme
- "Cleaning up" the cts_idx local to the moment breaks BOS_0 selection (window [start, cts_idx)), range_start_idx, the sd-prox gate and the POI inner resolver.
- Unlike CTS, BOS state is built from the emitted idx, so it must be decoupled first.

9. Contract and doc drift
- Changing what CTS_ESTABLISHED.idx means is not forbidden by the letter of the LANDMINES Event Contract rules (type names, meta fields, append-only, structure_id). It is still a semantic change to a frozen type.
- Many docs and memory entries assert "CTS_ESTABLISHED.idx = extreme": ARCHITECTURE, GLOSSARY:217, LANDMINES:493, structure_lifecycle.py:71-99, reference_zone.py:91-93, MEMORY "Key Architecture Points". So do external CSV readers.
- Everything must move in the same commit; otherwise future sessions implement against stale docs.

10. Plan D's meta cts_established_idx = int(ev.idx) silently becomes the moment at the flip (3 POI cells) unless Q5 is decided first.

11. Residual exceptions remain after an EST-only flip
- BOS_CONFIRMED.idx is still an extreme.
- Pattern-path CTS_UPDATED.idx is an extreme with NO recorded moment (the §17.12 latent leak).
- So "ev.idx = moment" is still not universal, and readers must keep using accessors.
- Benefit for live mode: a flipped event is no longer back-dated. Its idx equals the candle at which it is emitted, which removes this look-ahead class.

12. Scope creep: a rename sweep over 863 "anchor" hits in 53 .py files and 368 in 18 .md files. Keep the renames in stage 4, separate from the behaviour stages.
