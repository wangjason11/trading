### frozen_bridge (16)

1. Event TYPE names: CTS_ESTABLISHED and BOS_CONFIRMED carry a past-tense 'moment' word, but their ev.idx is the price EXTREME; the moment is meta['confirmed_at']. State the rule explicitly: an event-type token in a name names the event, not its timing.
2. CTS_CONFIRMED / CTS_RECONFIRMED: ev.idx == meta['confirmed_at'] = the MOMENT (the only CTS/BOS events whose idx is a moment).
3. CTS_UPDATED: ev.idx = the new extreme. Moment = ev.idx on the raw path; unrecorded on the pattern path.
4. meta['confirmed_at'] on CTS_ESTABLISHED, BOS_CONFIRMED, CTS_CONFIRMED and CTS_RECONFIRMED = the MOMENT (already follows the standard).
5. CTS_CONFIRMED / CTS_RECONFIRMED meta['cts_anchor_idx'] = the CTS EXTREME at confirmation. Read 'anchor' as 'extreme'; local copies must be named *_extreme_idx.
6. CTS_ESTABLISHED meta['anchor_idx'] = the breakout pattern's first candle (neither moment nor extreme). REVERSAL_CANDIDATE / REVERSAL_WATCH_START meta['anchor_idx'] = the reversal anchor / close-break candle. Never equal to the KL-zone meta 'anchor_idx', which is an extreme and not frozen.
7. REVERSAL_CANDIDATE meta['apply_idx'] = the SCHEDULED moment (a prediction; the confirmed reversal is STATE_CHANGED(to=reversal).idx); meta['expires_idx'].
8. BOS_CONFIRMED meta['pb_start'] = the cycle's pullback-pattern apply candle = the pullback-path CTS_CONFIRMED MOMENT. None on cycle 0 and on proximity-only cycles. NOT yet in the table.
9. BOS_CONFIRMED meta['source'] = 'initial_prior_extreme' | 'pullback_extreme' (labels that use 'extreme' correctly). NOT yet in the table.
10. RANGE_STARTED meta['cts_idx'] / ['cts_price'] = the CTS EXTREME (a bare frozen name). The table currently says RANGE_* is not audited.
11. RANGE_STARTED meta['pullback_apply_idx'] / ['proximity_apply_idx'] = the CTS confirmation MOMENT. meta['start_idx'] / ['confirm_idx'] (offline range) = the range candidate / range confirmation candle.
12. STATE_CHANGED meta['effective_idx'] (defaults to ev.idx).
13. structure_events.csv 'idx' column = ev.idx, with the per-type meaning above.
14. structure_levels.csv 'time' = t[ev.idx] = the EXTREME's time for CTS_ESTABLISHED / CTS_UPDATED / BOS_CONFIRMED. Its 'meta' is a frozen copy of the event meta.
15. M15 coordinate note: only confirmed_at, apply_idx, anchor_idx and cts_anchor_idx (plus the dead confirmed_idx and bos_anchor_idx) are rebased to entity-absolute. RANGE_STARTED cts_idx / start_idx / confirm_idx / pullback_apply_idx, pb_start, effective_idx and expires_idx stay slice-local.
16. Event-type-derived identifiers and labels (_emit_cts_established, on_cts_established, stop_after_cts_established, _collect_cts_established, _find_cts_established, _handle_*_cts_established, ReferenceZone.source 'cts_established' / 'cts_confirmed', FibTracker phases 'pre_established' / 'established' / 'confirmed', df cts_event / bos_event, cts_phase_debug 'EST_OR_UPD', chart legend 'CTS (confirmed)') name the event or phase. The standard governs *_idx and *_time-valued names only.
