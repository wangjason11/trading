First, given our current proximity pips are:
1H: 9
15M: 6
5M: 3

The 1H proximity pip is set at 9, which ultimately means that if the total distance (or gap) between the 2 closest sd & opp_sd zone inners is 18 or less, there will almost be guaranteed multiple repeat triggers. Even a distance slightly farther than that would likely cause many repeat triggers as well. Therefore, in addition to setting narrow rules for BOS & CTS, we also need to set some based on the specific distance between the 2 zone inners we are referencing for proximity. I would like to set those minimum distance thresholds to:
1H: 40
15M: 25
5M: 12

Again for this set of narrow rules, the reference gap used to determine the distance should be the 2 zone inners that would trigger the sd & opp_sd proximities. If the gap, rounded to the nearest whole pip, is equal to or below the threshold (<=), then we apply rule 3 from the narrow rules you mentioned: at most one sd and one opp_sd trigger per cycle while the gap is below the threshold. Once the gap reaches more than the threshold pips, normal alternation resumes and there is no cap/limit on the # of triggers per side. Here given that our initial references use zone inner price, those would not change / update over time like bos & cts thresholds would due to zone expansion. However, those initial references can be changed if the price moves past that initial reference zone completely. 

Now to be consistent with adding counter sd subs zones to the parent CTS side as reference zones, I think we should also add confluence sd sub zones to the parent BOS side as reference zones. However, unlikely CTS side, we will limit what same sd sub zones can be used. Specifically, we only use same sd sub zones on the parent BOS side if the parent has a POI and the sub zones are “below” that parent POI (based on zoner inner), or where a pullback has to go farther past the parent POI zone to reach. Same sd sub zones meeting this condition can be used as reference. There are no limitations on what opp_sd sub zones can be used. 

The closest available zone inners that would form the smallest gap available will always be the thresholds used for proximity triggers. Now initially, when the price pulls back toward parent BOS, the closest possible sd side reference would always be the parent POI, if any (if none, the sd side reference will be parent BOS inner), since any sub zones must be further in the pullback direction to be qualified references. Now when price completely passes this zone after triggering proximity during pullback, then the reference would move to the inner of the next closest zone. Moving past the zone here means that the price has moved across the inner price and closed past the outer price. When this happens that zone’s inner will no longer be the proximity trigger, instead, the reference for this particular side will now be the inner of the next closest zone for the next trigger. This continues each time a reference zone is passed, until the next closest inner is the parent BOS inner. When the parent BOS inner becomes the reference on the sd side, then the sd reference will be locked in as the parent BOS inner for this cycle and can no longer change.

When the price rebounds, the initial reference will be the closest of counter sub’s POI / BOS and parent CTS, which is our newly implemented proximity logic. Here we apply the same reference update logic, where if the initial reference was POI, and the price moves across the POI inner & closes beyond the POI outer and the sub BOS inner is further than POI inner, the reference will be updated to the sub BOS inner for the next trigger. This continues until the parent CTS inner becomes the final reference on the opp_sd side, at which point we can no longer update it for proximity triggers on that side. 

And so, this should now work in tandem with the new set of narrow rules. The flow would be:
Each time a zone is passed and price moves further:
1. Identify / update references (starts initially with the inner of closest zones) per cycle, updates to next closest based on inner
2. Judge distance
    a. If too narrow: allow at most one sd and one opp_sd trigger per cycle after the update causes gap to go below threshold
    b. If not too narrow: no limit on alternation 
3. Reset counter for updated side each time the gap expands and if the gap was below threshold prior to the expansion (The counter only matters when gap is below threshold prior to the update because that’s when we limit the number of sd & opp_sd proximity triggers to 1. If the gap was already above threshold prior to expansion there would be no need to reset the counter since we do not limit triggers)

Each time a reference is updated (due to price closing past zone) and gap expands, the trigger counts reset for that side, even if after the update we are still below the threshold. For example, it could be the case that after the reference updates, the 1H gap is still too narrow (from 30 pips to 35 pips). In that case, the next trigger near the updated side after the reference update still counts as the 1st of that direction since we reset the count due to gap expansion. 

Now the other way that a reference would update in the same main cycle is when the sub reference forms a new cycle. Since the counter sub is opposite sd to main, when a new cycle forms, the references will form a closer BOS and POI, if any. When this happens, it would also be considered a reference update, and we would do 1-3 from the above flow. However, notice for 3, we specifically only reset counters when the gap expands, and so in this case we would skip 3 since each new cycle in the counter direction of parent would decrease the reference inners gap.

I believe when this update is applied to our dataset, in our main (0,1) here, that would mean the gap initially would be based on the main CTS inner (opp_sd) & main POI inner (sd). After sub_3 forms, at a certain point in its lifespan, there would be 3 total potential opp_sd reference lines: main CTS_1 inner, sub_3 BOS_1 inner, sub_3 POI_1 inner. The opp_sd proximity reference should be updated to be sub_3 POI_1 inner since that is the closest reference line to the main sd side (BOS). Again for both sd & opp_sd side references, we are trying to ultimately form the smallest gap given the available to use zones. 

Then when sub_3 cycle_2 forms, the opp_sd reference candidates would at a point be main CTS_1 inner, sub_3 BOS_2 inner, and sub_3 POI_2 inner. Again, the proximity opp_sd proximity reference at some point should be updated to sub_3 BOS_2, and later on sub_3 POI_2. This is due to the 2 zones forming at different times such that BOS_2 is available before POI_2, and when POI_2 is available, it replaces the BOS_2 reference. When opp_sd proximity reference is still sub_3 BOS_2, the gap shrinks to 45.9 pips. Afterwards, the price will actually surpass sid_0 POI_1 zone entirely after triggering a sd proximity. The sd side reference would now update to the BOS inner (and resetting the sd side trigger count if previously there was a limit emplaced). This time there is no need for trigger counter reset because the gap was never below 40 pips (counter is only needed once gap gets below 40). When the sid_0 POI_1 inner reference updates to sid_0 BOS_1 inner reference, the gap now becomes 67.7 pips. Next when sub_3 POI_2 becomes active and available, the opp_sd reference updates once again to 0.58096, and the gap now shrinks to 60.2 pips. Throughout this the gap never dips below 40 pips. Once either sd side reference updates to the main BOS or the opp_sd side reference updates to the main CTS, those references are locked and can no longer be updated in the same parent main cycle. 

Now back to subs that are in the same direction as the main structure, we only use their zones as reference if they are further away than the main structure POI reference. That means any confluence sub with POI or BOS inners are above the main structure cycle POI inner reference (or closer to the gap center), we ignore them. This would be the case on main (0,1) with sub_2 POI & BOS zones. However, on (1,2), we have a sub_4 POI & BOS that exists “below” based on the sd direction (in this case above in actual direction), So in the case when this happens, the update is always to the next closest inner when the previous reference zone is surpassed. Then if that next closest zone is surpassed again in the same way (price close above), then we repeat to the next closest zone based on inner, and so on until we hit the main structure BOS. Each time this happens, we again process the above mentioned 1-3 as the gap expands, which mirrors when the gap expands on the main CTS side.
